# Учёт ИТ-ресурсов

Учебный проект системы учёта оборудования, программ и других ИТ-ресурсов.
Ресурсы представлены вершинами графа с указанием типа; связи показывают состав,
размещение и зависимости. Пользователь изучает ресурсы, планирует обслуживание
и сообщает о событиях затронутым сотрудникам.

**Текущий этап — постановка задачи и анализ существующих решений.** Команда
готовит доклады по шести блокам; приложения и результатов его испытаний пока нет.

| Блок | Материал для подготовки |
|---|---|
| Видение и предметная область | [Назначение проекта](docs/01-vision.md), [предметная модель](docs/02-domain-model.md) |
| Интеграции: система задач и мессенджер | [Внешние подключения](docs/04-integrations.md), [доклад по трекеру](docs/08-task-tracker.md) |
| Оповещения: события, каналы и получатели | [Оповещения](docs/05-notifications.md) |
| Граф: готовые решения, хранение, сценарии и фильтры | [Граф ресурсов](docs/06-graph.md) |
| Регламентные работы | [Планирование обслуживания](docs/07-maintenance.md) |
| Проверка и испытания | [Порядок проверки](docs/10-testing.md) |

Для каждого доклада нужны постановка задачи, сравнение вариантов, входы и выходы
процесса, предварительное предложение и вопросы к команде. Рассмотрение, анализ
и испытание планируются вместе с подготовкой решения; выполненные проверки
отличаются от предложенных.

[Указатель материалов](docs/README.md) содержит остальные заметки.
[Открытые вопросы](docs/open-questions.md) сохраняют нерешённые вопросы команды.
Подробные спецификации, планы и стандарт отложены в ветке
[`codex/requirements-draft`](https://github.com/kosrusal/it_resource_accounting/tree/codex/requirements-draft).
Они не входят в текущий объём защиты. Изменения готовятся в отдельной ветке,
проверяются и затем объединяются с `main`.

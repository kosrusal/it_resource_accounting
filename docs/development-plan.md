# План разработки программного обеспечения

Состояние: начальная редакция для начала курсового проекта. Кода приложения пока
нет. Сроки и персональные назначения не утверждены. Основание —
[гайд по курсовому проекту](https://false-wish-4b2.notion.site/5bc7650b121c4feb84a7408cab4d779a).

## 1. Определения

Этап — часть разработки с заданными входами, работами и выходами. Приращение —
согласованный набор возможностей, выпускаемый совместно. Интеграция ПО — соединение
компонентов и проверка их совместной работы. Объединение изменений в Git — включение
подготовленной ветки в `main`; оно применяется и к документации. Приёмка — проверка
результата по требованиям. Остальные термины определены в
[стандарте требований](requirements-standard.md) и [плане управления конфигурацией](configuration-management.md).

## 2. Жизненный цикл

Для каждого приращения выполняется одна последовательность. Найденное противоречие
возвращается на соответствующий предыдущий этап с записью причины.

| Этап | Вход и условие начала | Работы | Выход и условие завершения |
|---|---|---|---|
| Требования | Тема, гайд, сценарии, доступ к документам | Уточнение границ, формулировка требований, связи с источниками, способы проверки | Проект пяти документов; для перехода к реализации конкретной функции закрыты влияющие на неё вопросы |
| Проектирование | Проверенные требования выбранного приращения | Выбор технологий, разделение компонентов, описание данных и интерфейсов | Решения 02–09 приведены к требованиям; выбраны необходимые внешние системы и условия испытаний |
| Кодирование | Проектные решения, среда и проверяемые требования | Реализация компонентов и относящихся к ним проверок | Компоненты собираются, проверки проходят, есть инструкция запуска |
| Интеграция | Проверенные компоненты и согласованные интерфейсы | Совместная сборка, проверка прав, отказов и повторов на учебных данных | Работают сценарии приращения; результаты проверок записаны; неизвестные сбои зарегистрированы |
| Приёмка | Собранная редакция и протоколы | Демонстрация сценариев и проверка ограничений | Решение о принятии либо список доработок с номерами требований |

## 3. Организация работ и зависимости

Автор требований отвечает за спецификации; проектировщик — за решения 02–09;
разработчик — за код и проверки компонента; проверяющий — за сценарии приёмки;
ответственный за объединение — за согласованный состав `main`. Имена, календарные
даты и согласующий от команды должны быть записаны по ОВ-01 до распределения работ.

Первое приращение содержит реестр, доступ, владение и заявки. Граф нужен до аварийных
оповещений: прежний порядок, где оповещения зависели от более позднего этапа графа,
исправлен. Экраны, зависящие от ещё не созданных функций, выполняются вместе с этими
функциями; номер раздела перечня задач сам по себе не задаёт срок реализации.

| Приращение | Состав | Условие включения |
|---|---|---|
| 1. Основа учёта | E0–E3, E6; части E4 и E5 для реестра, владения и заявок | Доступ, переходы и выдача проверяются совместно; зависимые экраны уведомлений и отчётов перенесены к их функциям |
| 2. Задачи, граф и оповещения | E7, E9, E8; соответствующие экраны E4 и E5 | Расчёт влияния E9 готов до сценария объявления аварии E8 |
| 3. Расширение | E10, E11, E13; оставшиеся экраны | Используются проверенные функции предыдущих приращений |
| Сквозные работы | E12 и наблюдаемость | Выполняются с первого работающего компонента, а не после всех функций |

Оценки в [перечне задач](backlog.md) предварительные и не являются календарным
обязательством. Фактический состав демонстрации первого этапа определяется командой
по ОВ-02; приведённый порядок устраняет зависимости от ещё не выполненных работ.

## 4. Среды разработки и проверки

| Этап | Среда и материалы |
|---|---|
| Требования | Markdown, Git, общее хранилище GitHub, гайд; проверка документов через PowerShell 7 |
| Проектирование | Текстовые описания, схемы, искусственные примеры данных; выбор технологий по ОВ-03 |
| Кодирование | Локальная среда выбранного языка, учебные данные и испытательные заменители внешних систем; состав пока не выбран |
| Интеграция | Отдельная учебная среда, согласованные версии компонентов, пробные внешние проекты; реальные данные организации не требуются |
| Приёмка | Зафиксированная редакция, подготовленные наборы данных, протокол с условиями запуска и результатами |

Оборудование, число одновременных пользователей и порядок измерения времени ответа
фиксируются по ОВ-04 до испытаний производительности. Число учётных записей не
считается числом одновременных запросов.

## 5. Применяемые правила и контроль

Требования оформляются по [стандарту](requirements-standard.md), изменения — по
[плану управления конфигурацией](configuration-management.md), русский текст —
по [AGENTS.md](../AGENTS.md). Правила кода и автоматической сборки определяются после
выбора языка; их наличие пока не заявляется.

Для каждой демонстрации записываются идентификатор редакции, покрытые требования,
условия, фактический результат и обнаруженные отклонения. Сейчас выполнены только
проверки документов. Сценарии, описанные в спецификациях, предназначены для будущей
реализации и не считаются успешно пройденными испытаниями ПО.

Уровни испытаний, учебные данные и составные случаи описаны в
[разделе 10](10-testing.md); их протоколы используют номера общих спецификаций.

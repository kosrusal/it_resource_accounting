# Правила работы команды

Редакция 0.1. Проект для утверждения командой.

Документы этого каталога предназначены для участников проекта, а не для
пользователей системы. Они отвечают на процедурные вопросы: откуда взять входные
материалы, что сделать, куда положить результат, в каком виде и кто его проверяет.
Если ответа на процедурный вопрос нет ни в одном документе ниже, это недостаток
правил: участник регистрирует его по [ИН-08](procedures.md#ин-08-введение-нового-мероприятия).

## 2. Основные правила

1. Работа выполняется только по задаче на доске проекта. Задача без указанных входа
   и ожидаемого выхода в работу не берётся.
2. Любое изменение хранилища готовится в отдельной ветке и попадает в `main` только
   через запрос на объединение, рассмотренный другим участником.
3. Новое мероприятие сначала описывается в [инструкциях](procedures.md), затем
   выполняется. Описывается то, что уже известно; правило дополняется при первом
   новом случае.
4. Результат считается готовым, когда он лежит в `main` в указанном задачей месте,
   а задача закрыта со ссылкой на запрос на объединение.
5. Нерешённый вопрос не решается молчанием: он записывается в
   [открытые вопросы](../open-questions.md) с номером ОВ.

## 3. Сквозная схема работы

```
Задача на доске (вход, ожидаемый выход, исполнитель)
   │
   ▼
Ветка <автор>/<номер задачи>-<тема> от актуального main
   │  работа по инструкции ИН-NN
   ▼
Фиксации с описанием и ссылкой на задачу
   │
   ▼
Запрос на объединение → рассмотрение (ИН-05) → исправления
   │
   ▼
Объединение с main → задача закрывается автоматически → «Готово»
```

## 4. Роли

| Роль | Обязанности |
|---|---|
| Руководитель проекта | Утверждает правила, состав этапов и базовые редакции; распределяет направления |
| Ответственный за направление | Ведёт задачи своего направления, следит за его разделами и открытыми вопросами |
| Автор | Выполняет задачу, готовит ветку и запрос на объединение |
| Проверяющий | Рассматривает результат по [ИН-05](procedures.md#ин-05-рассмотрение-результата); не может быть автором того же изменения |
| Ответственный за объединение | Владелец хранилища (учётная запись `kosrusal`) или назначенный им участник; включает рассмотренные изменения в `main`, ставит метки базовых редакций |

Один участник может совмещать роли, кроме роли автора и проверяющего одного
изменения. Распределение направлений между участниками записывается в описании
доски проекта и в ОВ-01 после решения команды.

## 5. Порядок изменения правил

Правила меняются так же, как остальные материалы: задача с видом `процесс`,
ветка, запрос на объединение. Изменение правил рассматривает руководитель проекта.
Номер редакции в начале документа увеличивается при каждом объединённом изменении.

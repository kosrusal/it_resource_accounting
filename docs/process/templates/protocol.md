## 1. Применение

По этой форме оформляется каждый протокол формальной инспекции. Форму копируют в файл `docs/verification/pi-<имя файла документа без расширения>-NN.md`, угловые скобки заменяют значениями.

## 2. Форма протокола

```markdown
# Протокол инспекции <обозначение объекта>

| Реквизит | Значение |
|---|---|
| Обозначение протокола | ПИ-<КОД>-NN |
| Вид | предварительная / итоговая |
| Очерёдность | первичная / повторная (ссылка на прежний протокол: ПИ-<КОД>-NN) |
| Объект: файл | `<путь к файлу>` |
| Объект: обозначение | <обозначение> |
| Объект: проверяемая версия | <версия> |
| Автор объекта | <фамилия имя> |
| Ведущий | <фамилия имя> |
| Инспектор | <фамилия имя> |
| Категория контроля | КК2 |

## 1. Формальная часть

| Код | Вопрос | Ответ | Основание |
|---|---|---|---|
| <код из чек-листа> | <вопрос чек-листа> | да / нет | <где подтверждение или номер замечания> |

## 2. Экспертная часть

| Код | Вопрос | Ответ | Основание |
|---|---|---|---|
| <код из чек-листа> | <вопрос чек-листа> | да / нет | <где подтверждение или номер замечания> |

## 3. Замечания

| № | Место | Что не так | Что требуется |
|---|---|---|---|
| 1 | <раздел, строка, код бизнес-требования> | <как есть> | <как должно быть> |

Каждое замечание связано с ответом «нет» и с сообщением о проблеме в Issues (номер СП-NN указывается в основании).

## 4. Заключение

Заключение: принять / доработать.

Принять — все ответы «да». Доработать — есть хотя бы один ответ «нет». В предварительном протоколе заключение решения о принятии не содержит.

## 5. Подписи

|---|---|---|
| Инспектор | | |
| Ведущий | | |
```

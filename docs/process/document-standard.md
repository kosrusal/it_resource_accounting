## 1. Назначение

Стандарт задаёт формат, имена, обозначения, реквизиты, состояния и структуру документов хранилища. Исполнитель оформляет документ без обращения к другим лицам. Шаблон документа: [Ш-ДОК](templates/document.md).

## 2. Формат и именование файлов

### 2.1. Формат

Документ — файл Markdown в кодировке UTF-8. Язык текста определяет файл `AGENTS.md` в корне хранилища. Даты создания и изменения документа не указываются. Ссылка на семинар указывается его датой; слова заказчика передаются пересказом, без дословных цитат.

### 2.2. Имена и места хранения

Имя файла: латинские строчные буквы и цифры, слова через дефис, без пробелов и кириллицы, расширение `.md`.

| Вид документа | Каталог | Имя файла | Обозначение |
|---|---|---|---|
| Правила работы команды | docs/process | README.md | ПРК |
| План разработки | docs/process | development-plan.md | ПЛР |
| План управления конфигурацией | docs/process | configuration-management.md | ПКУ |
| План верификации | docs/process | verification-plan.md | ПВР |
| Процедура формальной инспекции | docs/process | inspection-procedure.md | ПФИ |
| Чек-лист инспекции постановки задачи | docs/process | checklist-business-requirements.md | ЧЛ-БТ |

| Стандарт оформления документов | docs/process | document-standard.md | СОД |
| Шаблон протокола инспекции | docs/process/templates | protocol.md | Ш-ПИ |
| Шаблон документа | docs/process/templates | document.md | Ш-ДОК |
| Постановка задачи, общая часть | docs/requirements | problem-statement.md | ПЗ |

`<имя раздела>` — имя файла раздела без расширения; `NN` — двузначный порядковый номер.

## 3. Обозначения

- Раздел постановки: ПЗ-`<КОД>`, где `<КОД>` — прописные буквы кода раздела (например, ПЗ-УЧ).
- Протокол: ПИ-`<КОД>`-NN; для общей части постановки — ПИ-ПЗ-NN.
- Отчёт анализа покрытия: АП-NN.
- Бизнес-требование: БТ-`<КОД>`-NN. Задача заказчика: З-NN.
- Сообщение о проблеме: СП-NN. Запрос на изменение: ЗИ-NN.

Номер NN присваивается по порядку без пропусков и не используется повторно.

## 4. Реквизиты

### 4.1. Состав

Сразу после заголовка первого уровня стоит таблица из двух столбцов «Реквизит | Значение» со строками в таком порядке:

| Реквизит | Правило |
|---|---|
| Обозначение | Из раздела 3; совпадает с таблицей раздела 2.2 |
| Версия | Из раздела 5.2; совпадает с последней строкой листа изменений |
| Состояние | Из раздела 5.1 |
| Автор | Фамилия и имя автора; для автора с неизвестной фамилией — только имя |
| Категория контроля | Категория, к которой документ относится после принятия (КК1 или КК2 по плану управления конфигурацией); до принятия черновик изменяется автором по правилам КК2 (ПКУ, раздел 5) |

Значения вносятся в самом файле, а не только в системе версий.

### 4.2. Протоколы и отчёты

Протокол оформляется по шаблону Ш-ПИ: реквизиты без версии и без листа изменений. Протокол и отчёт анализа разовые, не изменяются; повторная проверка оформляется новым протоколом со ссылкой на прежний.

## 5. Состояния и версии

### 5.1. Состояния

| Состояние | Кому присваивается | Условие |
|---|---|---|
| Черновик | Документы разработки | Документ создан или исправлен, итоговый протокол без замечаний отсутствует |
| Принят | Документы разработки | Есть протокол инспекции, в котором на все пункты чек-листа дан ответ «да» |
| Действует | Правила: планы, стандарты, шаблоны, чек-листы | Запрос на объединение в основную ветку одобрен другим участником |

Сменить «Черновик» на «Принят» может только протокол.

### 5.2. Версии

- Первая редакция: 0.1, «Черновик».
- Исправление по замечаниям инспекции: 0.2, «Черновик»; при повторных исправлениях следующий номер 0.3 и далее.
- Протокол без замечаний: 1.0, «Принят».
- Изменение принятого документа: 1.1, затем 1.2 и далее; допускается только после повторной инспекции.
- Правила (состояние «Действует») создаются с версией 1.0; каждое изменение увеличивает второй номер.

## 6. Структура и оформление

- Один заголовок первого уровня — название документа.
- Разделы нумеруются сквозь: «## 1. Название», «### 1.1. Название». Нумеруются все разделы, включая лист изменений.
- В каждой строке таблицы число ячеек равно числу столбцов заголовка.
- Ссылки на другие файлы относительные и ведут на существующий файл.
- Схемы приводятся в текстовом виде (список, таблица, блок кода) рядом с документом, а не изображением.
- Лист изменений обязателен и стоит последним разделом: таблица «Версия | Автор | Изменение», по строке на каждую версию, в порядке возрастания. Версия последней строки совпадает с версией в реквизитах.
- Объём указывается в страницах. Страница — 3000 знаков текста с пробелами без учёта реквизитов, листа изменений и разметки.

## 7. Контроль соблюдения

Соблюдение стандарта проверяет служба качества: формальную часть инспекции документов разработки и рассмотрение запросов на объединение для правил. Запрос на объединение, нарушающий стандарт, возвращается автору с перечнем нарушенных пунктов.

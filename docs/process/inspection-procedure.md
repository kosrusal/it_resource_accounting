# Процедура формальной инспекции

| Реквизит | Значение |
|---|---|
| Обозначение | ПФИ |
| Версия | 1.0 |
| Состояние | Действует |
| Автор | Тихонов Дмитрий |
| Категория контроля | КК2 |

## 1. Назначение

Документ задаёт порядок формальной инспекции документа разработки: роли, вход, шаги, решение и оформление протокола. Метод и состав проверок по этапам задан в ПВР.

Инспекция имеет три свойства: процедура записана, роли распределены, результаты зарегистрированы в протоколе.

## 2. Роли

| Роль | Кто | Что делает |
|---|---|---|
| Автор | Участник, создавший документ | Передаёт документ, исправляет замечания |
| Инспектор | Участник, не являющийся автором | Отвечает на вопросы чек-листа, регистрирует замечания |
| Ведущий | Участник по ПРК | Назначает инспектора, следит за соблюдением процедуры, оформляет протокол |

1. Автор не может быть инспектором своего документа.
2. Ведущий может быть инспектором, если не является автором.
3. Служба качества по ПРК может выполнять формальную часть вместо инспектора. Экспертную часть выполняет инспектор.

## 3. Вход

| Вход | Откуда |
|---|---|
| Проверяемый документ с реквизитами в состоянии «Черновик» | Ветка автора |
| Входные документы этапа, из которых получен документ | Хранилище, согласно ПКУ |
| Стандарты: СОД, СТТ | `docs/process/` |
| Чек-лист для вида документа | `docs/process/` |
| Протокол предыдущей инспекции (при повторной) | `docs/verification/` |

Без любого из этих входов инспекция не начинается.

## 4. Ход инспекции

| Шаг | Действие | Кто |
|---|---|---|
| 1. Подготовка | Автор передаёт документ в состоянии «Черновик» и сообщает в задаче. Ведущий назначает инспектора, не являющегося автором. Фиксируется проверяемая версия. Пока идёт инспекция, автор документ не изменяет | Автор, ведущий |
| 2. Формальная часть | Ответ «да» или «нет» на каждый вопрос формальной части чек-листа | Инспектор или служба качества |
| 3. Экспертная часть | Ответ «да» или «нет» на каждый вопрос экспертной части чек-листа | Инспектор |
| 4. Регистрация | Каждый ответ «нет» оформляется замечанием: место, что не так, что требуется. На каждое замечание заводится сообщение о проблеме в Issues | Инспектор, ведущий |
| 5. Заключение | Заключение «принять», если все ответы «да»; иначе «доработать». Ведущий проверяет полноту протокола, инспектор и ведущий подписывают его | Инспектор, ведущий |

Правила ответов:

1. Допустимы только «да» и «нет».
2. Ответ «нет» без записанного основания недопустим. К ответу «да» указывается основание: где в документе подтверждение.
3. Отсутствие доказательства равно ответу «нет».
4. Замечание описывает только факты: как должно быть и как есть. Способ исправления в замечании не указывается.

## 5. Решение

| Результат | Действия |
|---|---|
| Все ответы «да» | Автор ставит документу состояние «Принят» и версию 1.0, добавляет в лист изменений строку со ссылкой на протокол. Документ переходит в КК1. Изменения вносятся только по ПКУ |
| Есть ответы «нет» | Автор исправляет документ по замечаниям и повышает версию на 0.1 (0.1 → 0.2). Состояние остаётся «Черновик». Выполняется повторная инспекция |

Повторная инспекция:

1. Оформляется новым протоколом со ссылкой на прежний.
2. Проверяет весь чек-лист, а не только исправленные места.
3. Инспектор может быть тот же. Автором не может быть.

Состояние «Принят» устанавливается только на основании протокола с заключением «принять».

## 6. Протокол

1. Форма задана в Ш-ПИ.
2. Обозначение ПИ-<КОД>-NN, где КОД — код документа, NN — сквозной номер протокола этого документа.
3. Имя файла по СОД: `pi-<имя файла документа без расширения>-NN.md`.
4. Хранится в `docs/verification/`, категория контроля КК2.
5. Протокол разовый, версий не имеет и не изменяется. Ошибка в протоколе исправляется новым протоколом со ссылкой на прежний.
6. Протокол вводится в хранилище запросом на объединение, который рассматривает участник, не являющийся инспектором.

## 7. Предварительная инспекция

1. Может выполняться автоматизированно, в том числе ИИ-агентом, по тому же чек-листу.
2. Протокол оформляется по Ш-ПИ и помечается видом «предварительная».
3. Документ по предварительной инспекции не принимается и не меняет состояние.
4. Решение о принятии содержится только в итоговом протоколе инспектора-участника.
5. Автор может исправить замечания предварительного протокола до итоговой инспекции. Исправление повышает версию на 0.1.

## 8. Выход

| Выход | Назначение |
|---|---|
| Протокол ПИ-<КОД>-NN | Основание для смены состояния документа |
| Перечень замечаний | Вход для исправления автором |
| Сообщения о проблемах | Регистрация несоответствий в Issues |
| Заполненный чек-лист (в составе протокола) | Доказательство проверки |

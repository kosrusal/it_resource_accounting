# План верификации

| Реквизит | Значение |
|---|---|
| Обозначение | ПВР |
| Версия | 1.0 |
| Состояние | Действует |
| Автор | Тихонов Дмитрий |
| Категория контроля | КК2 |

## 1. Назначение

Документ определяет, что, когда, каким методом и кем проверяется, и куда кладутся результаты проверки. Верификация находит и регистрирует несоответствия. Исправляет их автор проверяемого результата.

Порядок формальной инспекции задан в ПФИ. Вопросы инспекции постановки задачи заданы в ЧЛ-БТ. Образец протокола задан в Ш-ПИ.

## 2. Методы верификации

Допускаются три метода. Других методов нет.

| Метод | Определение | Результат |
|---|---|---|
| Рассмотрение | Качественная оценка результата по контрольным вопросам. Виды: формальная инспекция по чек-листу; рассмотрение запроса на объединение другим участником | Протокол инспекции; одобрение или замечания в запросе на объединение |
| Анализ | Исследование количественных свойств результата, например полноты покрытия. Результат воспроизводим и выражен числом | Отчёт анализа АП-NN |
| Испытание | Исполнение результата и фиксация фактического поведения | Протокол испытаний |

## 3. Принцип независимости

1. Автор не проверяет собственную работу: не назначается инспектором, не выполняет анализ и не рассматривает свой запрос на объединение.
2. Ведущий инспекции, не являющийся автором объекта, может быть инспектором того же объекта. Ведущий, являющийся автором, передаёт ведение заместителю по ПРК.
3. Проверяющего назначает ведущий инспекции. Назначение записывается в задаче и в протоколе.

## 4. Что каким методом проходит

| Результат | Метод | Формальная инспекция |
|---|---|---|
| Документы разработки: постановка и её разделы, системные требования, требования к ПО, проект | Формальная инспекция | Проходит |
| Планы, стандарты, шаблоны, чек-листы | Только рассмотрение запроса на объединение | Не проходит |
| Протоколы и отчёты анализа | Не проверяются, не изменяются | Не проходит |
| Любое изменение хранилища | Рассмотрение запроса на объединение другим участником | Не заменяет формальную инспекцию |

Чек-лист для каждого вида документа разработки утверждается запросом на объединение до первой инспекции этого вида. Проверка по чек-листу, которого нет, не выполняется.

## 5. План проверок по этапам

Этапы заданы в плане разработки (ПЛР). На каждом этапе проверка его выхода запланирована заранее.

| Этап | Что проверяем | Метод | Кто проверяет | Результат | Где хранится |
|---|---|---|---|---|---|
| 1. Постановка задачи | Общая часть и каждый раздел постановки: по ЧЛ-БТ | Рассмотрение: формальная инспекция | Инспектор, не автор документа | Протокол ПИ-<КОД>-NN | `docs/verification/` |
| 1. Постановка задачи | Покрытие: каждая задача заказчика уточнена хотя бы одним бизнес-требованием; каждое бизнес-требование ссылается на задачу | Анализ покрытия | Участник, не автор проверяемых документов | Отчёт АП-NN | `docs/verification/` |
| 2. Системные требования | Спецификация системных требований: по чек-листу этапа | Рассмотрение: формальная инспекция | Инспектор, не автор | Протокол ПИ-<КОД>-NN | `docs/verification/` |
| 2. Системные требования | Покрытие бизнес-требований системными требованиями | Анализ покрытия | Участник, не автор | Отчёт АП-NN | `docs/verification/` |
| 3. Требования к ПО | Спецификация требований к ПО: по чек-листу этапа | Рассмотрение: формальная инспекция | Инспектор, не автор | Протокол ПИ-<КОД>-NN | `docs/verification/` |
| 3. Требования к ПО | Покрытие системных требований требованиями к ПО и испытаниями в обе стороны | Анализ покрытия | Участник, не автор | Отчёт АП-NN | `docs/verification/` |
| 4. Проектирование | Архитектура и требования низкого уровня: по чек-листу этапа | Рассмотрение: формальная инспекция | Инспектор, не автор | Протокол ПИ-<КОД>-NN | `docs/verification/` |
| 5. Кодирование | Код и тесты: по чек-листу кода | Рассмотрение кода | Участник, не автор кода | Протокол рассмотрения | `docs/verification/` |
| 5. Кодирование | Трассировка кода на требования низкого уровня и обратно | Анализ трассировки | Участник, не автор | Отчёт АП-NN | `docs/verification/` |
| 6. Интеграция и испытания | Собранное ПО против требований к ПО | Испытание | Участник, не автор испытываемого кода | Протокол испытаний | `docs/verification/` |
| Любой | Любое изменение хранилища | Рассмотрение запроса на объединение | Участник, не автор изменения | Одобрение или замечания в запросе | Хранилище |

Чек-листы и форма протокола для этапов 2–6 создаются до начала этапа. Проверка этапа завершена, когда по каждой его строке есть результат без открытых замечаний.

## 6. Выходы верификации

| Выход | Содержание | Правила |
|---|---|---|
| Протокол инспекции ПИ | Ответы по чек-листу, замечания, заключение | Разовый, без версий, КК2. Порядок по ПФИ |
| Отчёт анализа АП | Что сопоставлено, результат (число покрытых элементов и список непокрытых), заключение | Разовый, без версий, КК2. Повторный анализ — новый отчёт со ссылкой на прежний |
| Сообщение о проблеме СП | Как должно быть и как есть, без способа решения | Заводится в Issues с меткой «сообщение о проблеме». Для КК1 запускает управление изменениями по ПКУ |

Протоколы и отчёты не изменяются. Ошибка в них исправляется новым протоколом или отчётом со ссылкой на прежний.

## 7. Анализ покрытия

1. Что проверяется. Каждый элемент верхнего уровня уточнён хотя бы одним элементом нижнего уровня. На нижнем уровне нет элемента без источника на верхнем.
2. Вход. Принятые документы обоих уровней, у элементов которых есть идентификаторы и ссылки на источник (СТТ).
3. Кто. Участник, не автор проверяемых документов, назначенный ведущим.
4. Ход. Составить перечень идентификаторов верхнего уровня; для каждого найти ссылающиеся элементы нижнего уровня; составить обратный перечень ссылок нижнего уровня; найти элементы без ссылки и ссылки на несуществующие элементы.
5. Результат. Отчёт АП-NN в `docs/verification/`, КК2: число элементов каждого уровня, число покрытых, перечень непокрытых и лишних элементов, заключение «покрытие полное» или «покрытие неполное».
6. Каждый непокрытый или лишний элемент регистрируется как сообщение о проблеме. Этап не завершается при неполном покрытии.

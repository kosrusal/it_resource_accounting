# Учёт замечаний и запросов на изменение

Редакция 0.2. Проект.
Ответственный за ведение учёта: Байбурин Марсель.

## 1. Какие записи учитываются

В замечании описывается недостаток документа или другого результата работы.
В запросе на изменение — предлагаемое исправление или пересмотр согласованного
решения. Одно изменение может устранять несколько замечаний. В этом случае
сохраняются ссылки на все связанные замечания.

Документ описывает работу команды с её материалами, а не обслуживание серверов.
Он не добавляет функций системе учёта ИТ-ресурсов. Процедуру инспекции, стандарт
требований и правила слияния готовят ответственные за них участники. Здесь описан
только учёт полученных замечаний и решений.

Рабочие записи ведутся в очереди команды в Яндекс Трекере. Ответственный за настройку
указывает адрес очереди и определяет, каким состояниям в ней соответствуют состояния
из этого документа. Пока это не сделано, таблицы используются для подготовки записей.
Заполнение таблицы не означает, что задача уже создана. Этот документ не меняет настройки очереди.

## 2. Состав записи

| Поле замечания | Что записывается |
|---|---|
| Номер, автор, дата | Номер рабочей записи, кто и когда обнаружил недостаток. |
| Объект и редакция | Путь документа, идентификатор версии Git, раздел либо номер требования. |
| Наблюдение | Что именно написано, отсутствует или не соответствует проверяемому условию. |
| Основание | Применимое правило, задача или ожидаемый результат. Если правило не согласовано, записывается вопрос для обсуждения, а не утверждение о нарушении. |
| Значимость | Как недостаток мешает понять текст, выполнить действие, проверить результат или правильно оформить документ. |
| Ответственный и состояние | Кто рассматривает замечание, текущее состояние и следующий шаг. |
| Решение | Исправить, отклонить с причиной или связать с уже существующим замечанием. |
| Подтверждение закрытия | Изменённая редакция, результат повторной проверки, имя проверяющего и дата. |

| Поле запроса на изменение | Что записывается |
|---|---|
| Основание | Номера замечаний или отдельное поручение. |
| Предлагаемое изменение | Что меняется и какой результат требуется получить. |
| Область | Какие файлы и положения разрешено менять. Связанные документы других авторов перечисляются отдельно. |
| Влияние | Какие требования, примеры, ссылки или проверки затрагиваются. |
| Решение по запросу | Кто разрешил, отклонил или отложил изменение и почему. |
| Выполнение | Исполнитель, ветка, версии изменений и запрос на слияние. |
| Проверка | Другой участник, проверяемая версия, замечания и вывод. |
| Завершение | Версия после объединения либо основание закрытия без изменения. |

После обсуждения исходная формулировка замечания сохраняется. Уточнения добавляются
отдельно. Номер закрытой записи не используется для нового замечания. Пароли,
служебные ключи и закрытые данные в записи не помещаются.

## 3. Порядок обработки

| Этап | Исполнитель | Результат |
|---|---|---|
| Зарегистрировать | Участник, обнаруживший недостаток. | Запись с объектом, редакцией, наблюдением и основанием. |
| Проверить полноту | Ответственный за учёт. | Запрошены недостающие сведения. Записи об одном недостатке связаны между собой; первоначальные формулировки сохранены. |
| Принять решение | Автор затронутого раздела. Если спор касается нескольких направлений — руководитель команды вместе с ответственными за эти направления. | Записаны решение, его причина, исполнитель и перечень разрешённых изменений. |
| Подготовить исправление | Назначенный исполнитель. | Изменения в отдельной ветке со ссылкой на запрос; основная ветка не изменена. |
| Проверить исправление | Участник, который не является автором исправления. | Проверена указанная версия. Проверяющий подтвердил исправление или вернул запись исполнителю с объяснением причины. |
| Объединить и закрыть | Ответственный за объединение; затем ответственный за учёт. | После положительной проверки изменения объединены с основной веткой. В замечании указана полученная версия, затем запись закрыта. |

Для записей предлагаются состояния: «Зарегистрировано», «Рассматривается», «В работе»,
«На проверке», «Закрыто». Отклонённую запись или дубликат закрывают с указанием причины.
В дубликате также указывается ссылка на основную запись. Если недостаток обнаружен
повторно, запись открывают заново и указывают новую редакцию и причину повторного открытия.

Разрешение подготовить изменение ещё не означает, что готовое исправление проверено.
Самопроверка автора и автоматическая проверка разметки не заменяют рассмотрение
другим участником. Новая версия после исправления замечаний передаётся на повторную проверку.
Сам факт объединения также не доказывает, что замечание устранено.

## 4. Границы ответственности

Марсель следит за тем, чтобы замечания были учтены и связаны с результатами их
рассмотрения. Он не принимает технические решения за авторов других направлений.
В своей теме Марсель определяет содержание документов, но перед объединением
изменения всё равно проверяет другой участник.

Если замечание относится к чужому документу, указываются точное место и предлагаемое
решение. При исправлении материалов по обслуживанию чужие файлы не меняются.
Если нужны изменения в нескольких направлениях, работу заранее распределяют
между их авторами. Для каждого автора указывают разрешённые изменения и проверяющего.

## 5. Форма записи и сводка

```text
Вид: замечание / запрос на изменение.
Номер рабочей записи:
Автор и дата:
Документ, версия Git, раздел или номер требования:
Наблюдение либо предлагаемое изменение:
Основание и ожидаемый результат:
Связанные записи:
Разрешённая область изменения:
Решение, кто его принял и дата:
Исполнитель и состояние:
Следующий шаг:
Ветка, версия Git и запрос на слияние:
Проверяющий, проверенная версия и результат:
Основание закрытия:
```

Для промежуточного и итогового отчёта из рабочих записей составляется сводка:

| Номер | Объект | Ответственный | Состояние | Следующий шаг | Подтверждение закрытия |
|---|---|---|---|---|---|

Сводка содержит только существующие записи. Пустой шаблон не означает, что
замечаний нет. Запись об исправлении не закрывается до его проверки.
За проведение инспекции и общий перечень вопросов для неё отвечает участник,
назначенный проверять результаты. Форма учёта их не заменяет.

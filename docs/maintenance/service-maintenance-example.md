# Пример регламента: перезагрузка сервера базы знаний

Обозначение: РГ-БЗ-01. Редакция 0.1. Ответственный за документ: Байбурин Марсель.

Учебный пример организационного регламента для одного условного сервиса.
Работы не проводились. Команды конкретного сервера определяются его эксплуатационной
инструкцией; без неё пример не применяется к рабочей среде.

## 1. Обслуживаемый сервис и границы работ

Сервис «База знаний» предоставляет сотрудникам поиск и чтение инструкций,
а редакторам — изменение статей. В учебной схеме приложение работает на сервере
СЕРВЕР-БЗ-01; база данных и вложения находятся на отдельных ресурсах БД-БЗ-01
и ФАЙЛЫ-БЗ-01. Второго сервера приложения нет: на время перезагрузки весь сервис
недоступен. Это условия примера, не выбранная архитектура проекта.

Работа заключается в одной штатной перезагрузке СЕРВЕР-БЗ-01 по обоснованному
заданию. Обновление программ, изменение прав, перезагрузка базы данных и изменение
схемы размещения в эту работу не входят. Сам календарный срок не является основанием
перезагружать исправный сервер.

Результат успешной работы: сервер перезапущен, пользовательские действия из §5
проверены, доступ к базе знаний открыт, фактические сроки и результаты сохранены.

## 2. Участники и входные сведения

| Участник | Действие |
|---|---|
| Исполнитель | Проверяет готовность, выполняет перезагрузку и записывает результат. |
| Ответственный за сервис | Подтверждает допустимость периода, состав пользователей и решение при неудаче. |
| Проверяющий | Другой сотрудник, который выполняет контрольные действия пользователя после работ. |

Перед началом в задании указаны конкретные участники. Пароли, ключи и содержимое
закрытых статей в общедоступную документацию не включаются.

| Вход | Откуда получает исполнитель | Проверка до начала |
|---|---|---|
| Задание на обслуживание | Запись работ в используемой организацией системе задач. | Есть причина перезагрузки, точный ресурс, дата, период с часовым поясом, исполнитель, проверяющий и подтверждение ответственного. |
| Состав сервиса и зависимости | Карточка сервиса и сведения о размещении ресурсов. | Сервер однозначно сопоставлен с базой знаний; проверено, нет ли на нём других приложений и совпадающих работ. При расхождении план уточняется. |
| Инструкция перезагрузки и порядок восстановления | Эксплуатационные документы выбранной среды. | Понятны штатная остановка, перезапуск, запуск приложения, доступ к консоли и действия при отказе запуска. Копия доступна вне обслуживаемой базы знаний. |
| Сведения о резервных копиях | Журнал резервирования и инструкция восстановления сервиса. | Есть пригодные копии нужных данных и конфигурации, время их создания и подтверждение ранее проверенного способа восстановления. Наличие файла само по себе не считается такой проверкой. |
| Исходное состояние | Проверки §5 и средства наблюдения. | Все исходные проверки §5 пройдены; сохранены эталонные статья и вложение. Иные известные ошибки записаны отдельно. |
| Получатели и связь | Подтверждённый ответственным список пользователей сервиса. | Есть канал сообщения, доступный при отказе базы знаний, и способ связи с ответственным. Пользователи не заменены одним владельцем сервера. |

При отсутствии любого входа, необходимого для безопасного продолжения, работа
не начинается. Причина и требуемое уточнение записываются в задании.

### Учебное распределение времени

Для разбора принят период 20:00–20:30 по московскому времени; дата заполняется
в задании. До 20:05 отведено завершение пользовательских изменений, до 20:10 —
перезагрузка и запуск, до 20:20 — проверка, до 20:30 — наблюдение и подведение итога.
Эти значения — параметры примера, а не нормативы для всех сервисов.

До назначения реальных работ отдельно оценивается время восстановления. Если оно
не помещается в оставшийся период, заранее выбирается более длительный период.
Плановое окончание не является гарантией восстановления к этому моменту.

## 3. Последовательность выполнения

| Шаг | Действие исполнителя | Выход и условие продолжения |
|---|---|---|
| 1. Подготовить работу | Проверить входы §2, провести исходные проверки §5, подтвердить период и отсутствие неучтённых зависимостей. | Заполненное задание и исходные результаты. При неизвестном влиянии перезагрузку не выполнять. |
| 2. Предупредить пользователей | До начала сообщить название сервиса, период недоступности и контакт для связи. Проверить отправку выбранным способом. | Текст, время и подтверждённый результат отправки сохранены в задании; неизвестный результат не выдан за доставку. |
| 3. Подготовить наблюдение | Если применяется особый режим наблюдения, ограничить его СЕРВЕР-БЗ-01, сроком и ожидаемыми проблемами. Сохранить сбор измерений. | Сохранены параметры периода; проверки базы данных, хранилища и посторонних узлов не отключены. Без такого режима дежурный предупреждён об ожидаемых сигналах. |
| 4. Подтвердить начало | В согласованное время сообщить о начале. По инструкции прекратить новые изменения статей, дождаться завершения текущих записей и закрыть общий доступ к приложению. | Зафиксировано фактическое начало; незавершённых записей нет. Доступ до конца проверки оставлен только контрольным учётным записям. Если завершение записей не подтверждено, сервер не перезапускать. |
| 5. Перезагрузить сервер | По инструкции штатно остановить приложение и выполнить одну перезагрузку только СЕРВЕР-БЗ-01. | Время действий записано. Принятие команды не приравнивается к готовности сервиса. |
| 6. Проверить запуск | Через подготовленную консоль проверить запуск сервера и приложения, соединение с БД-БЗ-01 и ФАЙЛЫ-БЗ-01. | Доступны приложение и его зависимости. При отказе перейти к §4, не повторять перезагрузку без разбора причины. |
| 7. Проверить функции | Проверяющий выполняет первые шесть проверок §5. Проверка записи проводится на выделенной испытательной статье, не на рабочей инструкции. | Для каждого действия сохранены ожидаемый и фактический результат. Непройденная проверка исключает успешный итог. |
| 8. Вернуть обычный режим | После успешных проверок открыть пользовательский доступ, завершить особый режим наблюдения и проверить поступление новых измерений. | Сервис доступен пользователям; наблюдение вновь охватывает обычные условия. В течение оставшегося периода проверяется отсутствие повторных ошибок. |
| 9. Сообщить итог | Передать пользователям фактический результат. При ограничениях явно указать их; не использовать сообщение об успехе. | В задании сохранены итоговое сообщение и результат отправки. |
| 10. Закрыть запись работ | Сохранить отчёт §6. Обнаруженную проблему и применённое решение внести в материалы обслуживания. | Отчёт связан с заданием и версией регламента. Неустранённая проблема имеет отдельную запись и ответственного. |

## 4. Отклонения и восстановление

**Работы ещё не начались.** При недоступности консоли, непригодной копии, неизвестном
составе пользователей или неподтверждённом периоде перенести работы. Пользователям,
уже получившим предупреждение, сообщить о переносе или отмене.

**К 20:05 не завершены записи.** Перезагрузку не выполнять. Ответственный выбирает
перенос или новый период; решение сообщается пользователям. При отказе от перезагрузки
вернуть обычный доступ и режим наблюдения, затем проверить исходные функции.
Незавершённая запись не прерывается только ради соблюдения расписания.

**К 20:10 сервер или приложение не запустились.** Остановить плановые действия,
сохранить ошибки и время наблюдения, связаться с ответственным. Далее действует
подготовленная инструкция восстановления. Новые команды, изменение состава
сервиса и восстановление из копии без решения ответственного не выполняются.

**Функциональная проверка не пройдена.** Общий доступ не открывать; сохранить
конкретное действие и ошибку. Если неисправность выявлена после открытия, сообщить
о ней пользователям и ограничить доступ по решению ответственного. После восстановления повторить все проверки §5,
а не только ранее неудачную. Замена или возврат данных учитывают возможную потерю
изменений; база данных не восстанавливается автоматически из-за отказа сервера
приложения.

**Ожидается выход за 20:30.** До окончания объявленного периода сообщить о задержке,
ограничениях и времени следующего сообщения. Если срок восстановления неизвестен,
указать это прямо. Особый режим наблюдения не продлевать молча: его продолжение
подтверждается отдельно, обычные сообщения о новой неисправности не скрываются.

**Сервис не восстановлен.** Запись плановых работ завершается с неудачным результатом
и ссылкой на продолжающееся восстановление. Это не означает закрытия аварии.
Следующее действие, ответственный и время очередного сообщения определены.

## 5. Проверка результата

Те же эталонные данные используются до и после перезагрузки. Учётные записи имеют
разные права: читатель, редактор и пользователь без доступа к служебной статье.
После перезагрузки первые шесть проверок выполняются до открытия общего доступа;
проверка наблюдения — на шаге 8 после возврата обычного режима.

| Проверка | Действие | Успешный результат |
|---|---|---|
| Вход | Открыть обычный адрес сервиса с рабочего места и войти как читатель. | Вход выполнен, доступен обычный раздел инструкций. |
| Чтение | Открыть эталонную статью. | Название и содержание совпадают с зафиксированными до работ. |
| Поиск | Найти эталонную статью по заранее выбранному слову. | Статья присутствует в результатах и открывается. |
| Вложения | Получить эталонное вложение. | Файл доступен и совпадает с исходным образцом. |
| Запись | Как редактор изменить выделенную испытательную статью и открыть её заново. | Сохранён именно внесённый текст. Затем испытательная правка убрана. |
| Доступ | Как пользователь без права чтения запросить служебную статью и выполнить поиск её текста. | Служебное содержание не раскрыто ни при открытии, ни в результатах поиска. |
| Наблюдение | В обычном режиме наблюдения проверить новые измерения и состояние приложения. | Поступают текущие данные; нет новых ошибок, препятствующих проверенным функциям. |

В отчёте для каждой строки указываются время, проверяющий, фактический результат
и подтверждение: снимок экрана, запись наблюдения или описание выполненного действия.
Секреты и закрытое содержание в подтверждение не включаются. Доступность сервера
по сети без проверки функций не считается успешным результатом обслуживания.

## 6. Выходные материалы

| Выход | Состав | Куда помещается |
|---|---|---|
| Запись работ | Основание, ресурсы, участники, согласованный период, ссылка на РГ-БЗ-01 и его редакцию. | В задание на обслуживание. |
| Отчёт о выполнении | Фактические сроки, выполненные действия, результаты всех проверок, итог и оставшиеся ограничения. | В то же задание; закрытые подтверждения — в доступное участникам защищённое место со ссылкой. |
| Сообщения пользователям | План, начало, перенос или задержка при их наличии, фактический итог. | В согласованный канал; копия текста и результат отправки — в задание. |
| Запись о проблеме | Признаки неисправности, условия, проведённые действия, результат и следующий ответственный. | В используемую систему регистрации проблем; ссылка — в задание. |
| Найденное решение | Условия применимости, причина при её установлении, проверенные действия и результат. | В материалы обслуживания сервиса с доступом специалистам. |

Итог «Не выполнено» означает, что перезагрузка не начата; при проведённой подготовке
обычный доступ и наблюдение восстановлены. Если доступ восстановить не удалось,
итог — «Неудачно» с записью продолжающегося восстановления.

### Форма отчёта о конкретном выполнении

```text
Задание:
Сервис и обслуженный ресурс:
Регламент и редакция:
Исполнитель и проверяющий:
Плановое начало и окончание, часовой пояс:
Фактическое начало и окончание, часовой пояс:
Выполненные действия:
Результаты проверок §5 и ссылки на подтверждения:
Итог: успешно / не выполнено / неудачно.
Выполнялось ли восстановление; какие данные затронуты:
Оставшиеся ограничения и запись продолжающегося восстановления:
Кому, когда и какой итог передан:
Ссылка на сохранённое решение проблемы:
```

Форма не заполнена: она предназначена для будущего выполнения, а не изображает
проведённое испытание.

## 7. Примеры сообщений

**До начала:** «[Дата] с 20:00 до 20:30 по московскому времени база знаний будет
недоступна из-за перезагрузки сервера. До 20:00 завершите редактирование статей.
По вопросам работ обращайтесь к [контакт ответственного]».

**При задержке:** «Работы с базой знаний продолжаются, доступ пока не восстановлен.
Следующее сообщение — в [время и часовой пояс]. Точный срок восстановления пока
не установлен».

**После успешной проверки:** «Доступ к базе знаний восстановлен в [время и часовой
пояс]. Проверены вход, чтение, поиск, вложения и сохранение изменений».

**При переносе:** «Работы с базой знаний на [дата и период] отменены. Сервис работает
в обычном режиме. О новом периоде обслуживания сообщим отдельно».

Дата, контакты и фактический результат подставляются перед отправкой. Сообщение
об обычной работе сервиса используется только после проверки его состояния.

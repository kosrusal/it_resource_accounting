# Пример регламента: перезагрузка сервера базы знаний

Редакция 0.2. Проект.
Обозначение: РГ-БЗ-01. Ответственный за документ: Байбурин Марсель.

Учебный пример организационного регламента для одного условного сервиса.
Работы не проводились. Команды для конкретного сервера берутся из его эксплуатационной
инструкции. Без неё этот пример нельзя применять к рабочему серверу.

## 1. Обслуживаемый сервис и границы работ

Сервис «База знаний» предоставляет сотрудникам поиск и чтение инструкций,
а редакторам — изменение статей. В учебной схеме приложение работает на сервере
СЕРВЕР-БЗ-01; база данных и вложения находятся на отдельных ресурсах БД-БЗ-01
и ФАЙЛЫ-БЗ-01. Второго сервера приложения нет: на время перезагрузки весь сервис
недоступен. Это условия примера, не выбранная архитектура проекта.

По заданию, в котором указана причина работ, выполняется одна штатная перезагрузка
СЕРВЕР-БЗ-01. Обновление программ, изменение прав, перезагрузка базы данных и изменение
схемы размещения в эту работу не входят. Наступление даты в календаре само по себе не
служит причиной для перезагрузки исправного сервера.

Работа выполнена успешно, если сервер перезапущен, проверки из §5 пройдены,
доступ к базе знаний открыт, а фактические сроки и результаты записаны.

## 2. Участники и входные сведения

| Участник | Действие |
|---|---|
| Исполнитель | Проверяет готовность, выполняет перезагрузку и записывает результат. |
| Ответственный за сервис | Подтверждает выбранное время обслуживания, список пользователей и решение о действиях при неудаче. |
| Проверяющий | Другой сотрудник, который после работ проверяет действия пользователя по §5. |

До начала работ в задании указываются конкретные участники. Пароли, ключи и содержимое
закрытых статей в общедоступную документацию не включаются.

| Вход | Откуда получает исполнитель | Проверка до начала |
|---|---|---|
| Задание на обслуживание | Запись работ в используемой организацией системе задач. | Есть причина перезагрузки, точный ресурс, дата, период с часовым поясом, исполнитель, проверяющий и подтверждение ответственного. |
| Состав сервиса и зависимости | Карточка сервиса и сведения о размещении ресурсов. | Установлено, какой сервер обслуживает базу знаний. Проверено, нет ли на нём других приложений и не запланированы ли другие работы на то же время. При расхождении сведений план уточняется. |
| Инструкция перезагрузки и порядок восстановления | Эксплуатационные документы выбранной среды. | В инструкции описаны штатная остановка, перезагрузка, запуск приложения, доступ к консоли управления и действия при неудачном запуске. Копия инструкции доступна вне обслуживаемой базы знаний. |
| Сведения о резервных копиях | Журнал резервирования и инструкция восстановления сервиса. | Есть пригодные резервные копии нужных данных и настроек; указано время их создания. Есть подтверждение, что способ восстановления уже проверен. Одного наличия файла копии недостаточно. |
| Исходное состояние | Проверки §5 и средства наблюдения. | До начала работ пройдены все проверки §5. Сохранены статья и вложение для сравнения после перезагрузки. Другие известные ошибки записаны отдельно. |
| Получатели и связь | Подтверждённый ответственным список пользователей сервиса. | Есть канал отправки сообщений, доступный при отказе базы знаний, и способ связи с ответственным. В списке указаны пользователи сервиса, а не только владелец сервера. |

Если необходимых для безопасной работы сведений или средств нет, работа не начинается.
В задании записываются причина и то, что нужно подготовить или уточнить.

### Учебное распределение времени

Для разбора принят период 20:00–20:30 по московскому времени; дата заполняется
в задании. До 20:05 отведено завершение пользовательских изменений, до 20:10 —
перезагрузка и запуск, до 20:20 — проверка, до 20:30 — наблюдение и подведение итога.
Эти значения — параметры примера, а не нормативы для всех сервисов.

До назначения реальных работ отдельно оценивается время восстановления при неудаче.
Если оставшегося времени недостаточно, для обслуживания заранее выделяется более
длительный период. Само указание планового окончания не гарантирует, что сервис
удастся восстановить к этому времени.

## 3. Последовательность выполнения

| Шаг | Действие | Результат и условие продолжения |
|---|---|---|
| 1. Подготовить работу | Проверить готовность по §2, выполнить проверки §5 до начала работ, подтвердить время обслуживания и отсутствие неучтённых зависимостей. | Задание заполнено, результаты исходных проверок сохранены. Если неизвестно, на что повлияет перезагрузка, выполнять её нельзя. |
| 2. Предупредить пользователей | До начала сообщить название сервиса, период недоступности и контакт для связи. Проверить отправку выбранным способом. | В задании сохранены текст, время и подтверждённый результат отправки. Если результат неизвестен, сообщение не отмечается как доставленное. |
| 3. Подготовить наблюдение | Если применяется особый режим наблюдения, задать отдельные правила обработки ожидаемых проблем только для СЕРВЕР-БЗ-01 и только на время работ. Сбор измерений продолжить. | Сохранены параметры периода; проверки базы данных, хранилища и посторонних узлов не отключены. Если такой режим не используется, дежурный сотрудник, следящий за сообщениями о неисправностях, предупреждён об ожидаемой недоступности. |
| 4. Подтвердить начало | В согласованное время сообщить о начале. По инструкции запретить начало новых изменений статей, дождаться сохранения уже начатых изменений и закрыть общий доступ к приложению. | Фактическое начало записано; все начатые изменения сохранены. До конца проверки доступ оставлен только учётным записям, подготовленным для проверки. Если сохранение изменений не подтверждено, сервер не перезапускать. |
| 5. Перезагрузить сервер | По инструкции штатно остановить приложение и выполнить одну перезагрузку только СЕРВЕР-БЗ-01. | Время действий записано. Подтверждение приёма команды ещё не означает, что сервис готов к работе. |
| 6. Проверить запуск | Через подготовленную консоль проверить запуск сервера и приложения, соединение с БД-БЗ-01 и ФАЙЛЫ-БЗ-01. | Приложение запущено, соединения с базой данных и хранилищем доступны. При отказе перейти к §4. Не повторять перезагрузку без выяснения причины. |
| 7. Проверить функции | Проверяющий выполняет первые шесть проверок §5. Проверка записи проводится на выделенной испытательной статье, не на рабочей инструкции. | Для каждого действия сохранены ожидаемый и фактический результат. Если хотя бы одна проверка не пройдена, результат работ не считается успешным. |
| 8. Вернуть обычный режим | После успешных проверок открыть пользовательский доступ, завершить особый режим наблюдения и проверить поступление новых измерений. | Сервис доступен пользователям; наблюдение работает в обычном режиме. В течение оставшегося периода проверяется отсутствие повторных ошибок. |
| 9. Сообщить итог | Передать пользователям фактический результат. При ограничениях явно указать их; не использовать сообщение об успехе. | В задании сохранены итоговое сообщение и результат отправки. |
| 10. Закрыть запись работ | Сохранить отчёт §6. Обнаруженную проблему и применённое решение внести в материалы обслуживания. | Отчёт связан с заданием и версией регламента. Для неустранённой проблемы создана отдельная запись и назначен ответственный. |

## 4. Отклонения и восстановление

**Работы ещё не начались.** При недоступности консоли, непригодной копии, неизвестном
составе пользователей или неподтверждённом периоде перенести работы. Пользователям,
уже получившим предупреждение, сообщить о переносе или отмене.

**К 20:05 не сохранены начатые изменения.** Перезагрузку не выполнять. Ответственный выбирает
перенос или новый период; решение сообщается пользователям. При отказе от перезагрузки
вернуть обычный доступ и режим наблюдения, затем проверить исходные функции.
Сохранение начатых изменений не прерывается только ради соблюдения расписания.

**К 20:10 сервер или приложение не запустились.** Остановить плановые действия,
записать ошибки и время их обнаружения, связаться с ответственным. Дальнейшие
действия выполнять по подготовленной инструкции восстановления. Новые команды, изменение состава
сервиса и восстановление из копии без решения ответственного не выполняются.

**Функциональная проверка не пройдена.** Общий доступ не открывать; сохранить конкретное
действие и ошибку. Если неисправность выявлена после открытия, сообщить о ней
пользователям и ограничить доступ по решению ответственного. После восстановления
повторить все проверки §5, а не только ранее неудачную. При замене или восстановлении
данных учитывать возможную потерю изменений. Отказ сервера приложения сам по себе не
означает, что нужно восстанавливать базу данных из копии.

**Работы могут продлиться после 20:30.** До окончания объявленного периода сообщить о задержке,
ограничениях и времени следующего сообщения. Если срок восстановления неизвестен,
указать это прямо. Продление особого режима наблюдения согласовать отдельно. Сообщения о новых
неисправностях, которые поступают в обычном режиме, не скрывать.

**Сервис не восстановлен.** Запись плановых работ завершается с неудачным результатом
и ссылкой на продолжающееся восстановление. Это не означает закрытия аварии.
Указаны следующее действие, ответственный за него и время очередного сообщения.

## 5. Проверка результата

До и после перезагрузки для сравнения используются одни и те же статья и вложение.
Учётные записи имеют разные права: читатель, редактор и пользователь без доступа к
служебной статье. После перезагрузки первые шесть проверок выполняются до открытия
общего доступа; проверка наблюдения — на шаге 8 после возврата обычного режима.

| Проверка | Действие | Успешный результат |
|---|---|---|
| Вход | Открыть обычный адрес сервиса с рабочего места и войти как читатель. | Вход выполнен, доступен обычный раздел инструкций. |
| Чтение | Открыть эталонную статью. | Название и содержание совпадают с зафиксированными до работ. |
| Поиск | Найти эталонную статью по заранее выбранному слову. | Статья присутствует в результатах и открывается. |
| Вложения | Получить эталонное вложение. | Файл доступен и совпадает с исходным образцом. |
| Запись | Как редактор изменить выделенную испытательную статью и открыть её заново. | Сохранён именно внесённый текст. Затем испытательная правка убрана. |
| Доступ | Как пользователь без права чтения запросить служебную статью и выполнить поиск её текста. | Служебное содержание не раскрыто ни при открытии, ни в результатах поиска. |
| Наблюдение | В обычном режиме наблюдения проверить новые измерения и состояние приложения. | Поступают текущие данные; нет новых ошибок, препятствующих проверенным функциям. |

В отчёте для каждой строки указываются время, проверяющий, фактический результат
и подтверждение: снимок экрана, запись наблюдения или описание выполненного действия.
Пароли, ключи и закрытые сведения в подтверждающие материалы не включаются. Доступность сервера
по сети без проверки функций не считается успешным результатом обслуживания.

## 6. Выходные материалы

| Выход | Состав | Куда помещается |
|---|---|---|
| Запись работ | Основание, ресурсы, участники, согласованный период, ссылка на РГ-БЗ-01 и его редакцию. | В задание на обслуживание. |
| Отчёт о выполнении | Фактические сроки, выполненные действия, результаты всех проверок, итог и оставшиеся ограничения. | В то же задание. Закрытые подтверждающие материалы хранятся в защищённом месте, доступном участникам; в задании указывается ссылка. |
| Сообщения пользователям | План, начало, перенос или задержка при их наличии, фактический итог. | В согласованный канал; копия текста и результат отправки — в задание. |
| Запись о проблеме | Признаки неисправности, условия, проведённые действия, результат и следующий ответственный. | В используемую систему регистрации проблем; ссылка — в задание. |
| Найденное решение | Условия применимости, причина при её установлении, проверенные действия и результат. | В материалы обслуживания сервиса с доступом специалистам. |

Итог «Не выполнено» означает, что перезагрузка не началась. Если при подготовке менялись
доступ или режим наблюдения, они возвращены в обычное состояние. Если доступ
восстановить не удалось, итог — «Неудачно» с записью продолжающегося восстановления.

```text

Фактическое начало и окончание, часовой пояс:

Результаты проверок §5 и ссылки на подтверждения:

Выполнялось ли восстановление; какие данные затронуты:
Оставшиеся ограничения и запись продолжающегося восстановления:
Кому, когда и какой итог передан:
Ссылка на сохранённое решение проблемы:
```

Форма заполняется после выполнения работ. Сейчас она пуста: работы не проводились.

## 7. Примеры сообщений

**До начала:** «[Дата] с 20:00 до 20:30 по московскому времени база знаний будет
недоступна из-за перезагрузки сервера. До 20:00 завершите редактирование статей.
По вопросам работ обращайтесь к [контакт ответственного]».

**При задержке:** «Работы с базой знаний продолжаются, доступ пока не восстановлен.
Следующее сообщение — в [время и часовой пояс]. Точный срок восстановления пока
не установлен».

**После успешной проверки:** «Доступ к базе знаний восстановлен в [время и часовой
пояс]. Проверены вход, чтение, поиск, вложения и сохранение изменений».

**При переносе:** «Работы с базой знаний на [дата и период] отменены. Сервис работает
в обычном режиме. О новом периоде обслуживания сообщим отдельно».

Дата, контакты и фактический результат подставляются перед отправкой. Сообщение
об обычной работе сервиса используется только после проверки его состояния.

Объекты — [бизнес-требования](../business-requirements.md), редакция 0.1,
и [системные требования](../../requirements/maintenance-system.md), редакция 0.4,
в фиксации `b610b81fbf4470ce6fc1693d8fb11f8f5fb82d33`. Правила и смежные документы
использованы как входы. Это проверка своего направления, не заявление об инспекции
всех документов команды. Сами требования и документы других участников не изменены.

Результаты хранятся отдельно от требований в `docs/maintenance/verification/`
по правилу `docs/<направление>/` из [плана управления конфигурацией](../../process/configuration-management.md), §2.
Специальное место для отчётов анализа в плане пока не названо; путь зафиксирован
в задаче. Протокол и отчёт — разовые записи КК2 по заданию семинара, без редакций
и листов изменений. Исправленная редакция требований проверяется новым протоколом.
Общий план и чужие шаблоны этой работой не заменяются.

Рассмотрение и подсчёт выполнены ИИ-помощником, ранее участвовавшим в подготовке
текстов. Независимая инспекция участником команды и утверждение заказчиком
не заявляются. Публикация результатов по поручению пользователя не закрывает
замечания [#34](https://github.com/kosrusal/it_resource_accounting/issues/34)–[#40](https://github.com/kosrusal/it_resource_accounting/issues/40) и не переводит требования в принятое состояние.

Зафиксированная последовательность: проекты документов → проверка → замечания
и задачи на исправление. Следующие этапы — исправление автором, повторное
независимое рассмотрение и действительное решение о принятии — ещё не выполнены.

# Доклад о базе знаний

Моя часть проекта - база знаний. Её задача - собрать сведения о ресурсах так, чтобы специалист и обычный пользователь могли найти нужную им информацию.

Сейчас сведения и инструкции разрознены. Специалисту приходится искать настройки и порядок обслуживания в разных файлах. Пользователю нужна понятная инструкция по работе с сервисом. При этом служебные сведения нельзя автоматически открывать всем сотрудникам.

В базе знаний предусмотрены разные представления одного ресурса. Для ИТ-отдела - сервис, оборудование, системное программное обеспечение и настройки. Для пользователя - инструкция и описание доступных ему действий. Например, сотрудник видит, как пользоваться корпоративной почтой, а специалист - сведения об оборудовании, программах и настройках, которые обеспечивают её работу.

Я выделил пять требований: сохранять и обновлять сведения о ресурсе, просматривать их по нужным уровням, предоставлять пользовательские инструкции, искать доступные материалы и определять, кому они видны. Пока речь идёт об описании действий пользователя. Нужно ли выполнять эти действия прямо из системы, уточняется у заказчика.

Для сравнения рассмотрены Obsidian и Gramax. Obsidian подходит для связанных заметок, но в общем хранилище Sync у участников одинаковые права. Поэтому разделить инструкции для сотрудников и закрытые материалы ИТ-отдела таким способом не получится. В Gramax Enterprise разграничение доступа есть. Однако структуру наших ресурсов и четыре уровня просмотра потребуется организовать отдельно.

Мой блок отвечает за работу с материалами и их доступность. Регламенты обслуживания описывает Марсель. Выдача оборудования, граф и права сотрудников в самих сервисах относятся к другим блокам. HelpDesk и связь с мессенджерами не входят в проект.

До дальнейшей работы нужно уточнить, какие ресурсы описываем первыми, кто обновляет материалы и где проходит граница между пользовательской и служебной информацией. После этого можно согласовать раздел базы знаний с общей постановкой задачи.

# Системные требования: связь с системой ведения задач

**Состояние:** начальная редакция части E7. Документ входит в
[общую системную спецификацию](system.md) и охватывает только связь с внешними
задачами. Правила записи — [стандарт требований](../requirements-standard.md),
основание оформления — [гайд курса](https://false-wish-4b2.notion.site/5bc7650b121c4feb84a7408cab4d779a).
Устройство подключения вынесено в [раздел 08](../08-task-tracker.md).

## 1. Назначение и границы

Система учёта создаёт связанные внешние задачи по подтверждённым предметным событиям,
передаёт изменения и принимает разрешённые обратные действия. Создание собственного
средства ведения задач в часть E7 не входит. Правила выдачи и возврата ресурсов
задаются подсистемой заявок, а правила обслуживания — подсистемой работ.
Подключение использует эти правила и не заменяет их.

Требования применяются при включённом настроенном подключении. Недоступность
внешней системы обрабатывается по СТ-ТР-09–СТ-ТР-11; возможность создания задачи
подлежит проверке до включения подключения. Перенос комментариев рассматривается
как отдельное необязательное расширение и в текущий обязательный объём не входит.

## 2. Термины и участники

Термины таблицы 1 используются в требованиях таблицы 2.

**Таблица 1. Термины части E7**

| Термин | Значение |
|---|---|
| Внешняя система задач | Средство, в котором специалисты выполняют поручения |
| Связанная задача | Внешнее поручение с сохранённым соответствием исходной записи учёта |
| Исходная запись | Заявка, ресурс, кампания инвентаризации, расчёт с увольняемым сотрудником либо окно работ |
| Расчёт по ресурсам | Процедура возврата и передачи закреплённых ресурсов при увольнении; её начало отличается от кадрового запрета входа |
| Основание создания | Одна заявка, один срок ресурса, один расчёт по ресурсам, одно расхождение, один перевод в обслуживание либо одно окно |
| Срок ресурса | Вид срока и дата окончания для конкретного ресурса; например, окончание гарантии |
| Учётные сведения окна | Состояние, плановые и фактические сроки, состав ресурсов и результаты работ |
| Редакция | Версия сведений исходной записи после подтверждённого изменения |
| Сверка | Установление результата внешнего действия до решения о повторном создании |
| Участник внешнего изменения | Пользователь, выполнивший действие во внешней системе |
| Уполномоченный специалист | Пользователь с ролью специалиста либо руководителя ИТ-отдела и доступом к соответствующей исходной записи |
| Состояние передачи | «Ожидает», «передано», «повторяется», «требует сверки» либо «ошибка»; отличается от состояния заявки и задачи |

Сотрудник просматривает связь доступной заявки или ресурса. Специалист работает
с передачами и расхождениями. Руководитель ИТ-отдела настраивает подключение.
Общие права и области доступа определены в [разделе 01, §1.5](../01-vision.md).

## 3. Требования

Источник и способ проверки указаны в каждой строке. Проверки описывают будущую
приёмку; они не являются отчётом о работающем приложении.

| № | Требование | Источник | Проверка |
|---|---|---|---|

| СТ-ТР-02 | Система должна создавать задачу продления при выявлении срока лицензии, гарантии или сертификата, наступающего не позднее чем через 30 суток. | [04 §4.2](../04-integrations.md); [08 §8.2](../08-task-tracker.md) | Проверить границу 30 суток, позднее внесение и истёкший срок; для каждого основания появляется одна задача. |
| СТ-ТР-03 | Система должна создавать задачу с перечнем действующих закреплений ресурсов при начале расчёта с увольняемым сотрудником. | [01 §1.6 U8](../01-vision.md); [08 §8.2 Т3](../08-task-tracker.md) | Начать расчёт при незакрытых закреплениях и сравнить перечень задачи с учётными данными. |
| СТ-ТР-04 | Система должна создавать задачу по каждому выявленному расхождению инвентаризации. | [04 §4.2](../04-integrations.md); [08 §8.2 Т4](../08-task-tracker.md) | Зафиксировать два расхождения и проверить наличие двух связанных задач. |
| СТ-ТР-05 | Система должна создавать задачу обслуживания при переводе ресурса в обслуживание вне окна работ. | [04 §4.2](../04-integrations.md); [08 §8.2 Т5](../08-task-tracker.md) | Перевести ресурс в обслуживание без окна и проверить связанную задачу. |
| СТ-ТР-06 | Система должна создавать одну основную задачу для каждого окна работ после его первой публикации либо аварийного начала. | [07 §7.10](../07-maintenance.md); [08 §8.2 Т6](../08-task-tracker.md) | Опубликовать окно, затем изменить его и убедиться, что основная задача осталась одной. |
| СТ-ТР-07 | Система должна передавать изменение плановых сроков ранее опубликованного окна работ в его связанную задачу. | [07 §7.5, §7.10](../07-maintenance.md); [08 §8.5](../08-task-tracker.md) | Изменить сроки с возвратом плана на согласование; проверить обновление существующей задачи. |

| СТ-ТР-09 | Система должна показывать уполномоченному специалисту состояние передачи сведений во внешнюю систему. | [08 §8.5](../08-task-tracker.md); [E7-7](../backlog.md) | Проверить отображение всех пяти состояний: «ожидает», «передано», «повторяется», «требует сверки», «ошибка». |
| СТ-ТР-10 | Система должна сохранять учётные изменения при временной недоступности внешней системы ведения задач. | [03 §3.6](../03-architecture.md); [08 §8.5](../08-task-tracker.md) | Отключить внешнюю систему во время согласования заявки и проверить сохранение заявки. |

## 4. Условия принятия и прослеживаемость

Начальная редакция ещё не считается полной спецификацией готового подключения.
Не выбран внешний продукт, не подтверждены его способы удостоверения сообщений,
сверки и ограничения обмена. Причины и условия закрытия этих вопросов перечислены
в [разделе 08, §8.8](../08-task-tracker.md) со ссылками на ОВ-03 и ОВ-04.

Число 30 суток — предметный порог продления, перенесённый из сценария Т2.
Периодичность выявления и повторов относится к требованиям ПО; гарантированное
время доставки при отказе внешней системы здесь не устанавливается.
Для будущих измерений требуются согласованные условия и ограничения подключения.

Каждое уточнение [требований к ПО](tracker-software.md) содержит системный номер.
Составные случаи ТР-01 и далее в разделе 08 дополняют проверки. Номера сохраняются
при последующих изменениях; разработка остальных частей проекта в этот раздел не входит.

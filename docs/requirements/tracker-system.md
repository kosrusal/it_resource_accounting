# Системные требования: связь с системой ведения задач

**Состояние:** проект раздела системных требований. Этот документ охватывает только
связь учёта ресурсов с внешней системой ведения задач. Требования ко всей системе,
план управления конфигурацией, план разработки и стандарт требований оформляются
отдельно. Здесь описано, **что** должна делать система; устройство подключения
описано в [разделе 08](../08-task-tracker.md).

## Назначение и границы

Внешняя система ведения задач — средство, в котором специалисты выполняют поручения.
Заявка — обращение сотрудника о ресурсе. Окно работ — запланированное или аварийное
обслуживание одного или нескольких ресурсов. Связанная задача — поручение во внешней
системе, созданное по событию системы учёта.

Основания требований: сценарии [видения проекта](../01-vision.md), §1.6;
[интеграции](../04-integrations.md), §4.2; правила
[регламентных работ](../07-maintenance.md), §7.10; задачи E7
[перечня работ](../backlog.md). Конкретная внешняя система пока не выбрана.

## Функциональные требования

Каждое требование имеет собственный номер. Способ проверки указывает наблюдаемый
результат; он не предписывает способ реализации.

| № | Требование | Проверка |
|---|---|---|
| СТ-ТР-01 | Система должна создавать связанную задачу во внешней системе после согласования заявки на ресурс. | Согласовать заявку и установить наличие связанной внешней задачи. |
| СТ-ТР-02 | Система должна создавать задачу на продление ресурса за 30 суток до окончания лицензии, гарантии или сертификата. | Установить срок ресурса и проверить появление задачи за 30 суток до его окончания. |
| СТ-ТР-03 | Система должна создавать задачу на возврат ресурсов при начале увольнения сотрудника. | Начать увольнение сотрудника с выданными ресурсами и проверить задачу со списком этих ресурсов. |
| СТ-ТР-04 | Система должна создавать задачу по каждому выявленному расхождению инвентаризации. | Зафиксировать два расхождения и проверить наличие двух связанных задач. |
| СТ-ТР-05 | Система должна создавать задачу обслуживания при переводе ресурса в обслуживание вне окна работ. | Перевести ресурс в обслуживание без окна и проверить связанную задачу. |
| СТ-ТР-06 | Система должна создавать одну основную задачу для каждого окна работ после его первой публикации либо аварийного начала. | Опубликовать окно, затем изменить его и убедиться, что основная задача осталась одной. |
| СТ-ТР-07 | Система должна передавать изменения опубликованного окна работ в его связанную задачу. | Изменить срок окна и проверить срок в существующей внешней задаче. |
| СТ-ТР-08 | Система должна показывать пользователю связь доступной ему учётной сущности с внешней задачей. | Открыть заявку, ресурс и окно работ с правом просмотра; проверить ключ и ссылку. |
| СТ-ТР-09 | Система должна показывать уполномоченному специалисту состояние передачи сведений во внешнюю систему. | Проверить отображение ожидающей, выполненной, повторяемой передачи и передачи, требующей сверки. |
| СТ-ТР-10 | Система должна сохранять учётные изменения при временной недоступности внешней системы ведения задач. | Отключить внешнюю систему во время согласования заявки и проверить сохранение заявки. |
| СТ-ТР-11 | Система должна предотвращать создание второй внешней задачи при повторной обработке одного основания создания. | Повторить одно событие создания и проверить число внешних задач. |
| СТ-ТР-12 | Система должна проверять допустимость выполнения заявки до её завершения по сообщению о закрытии внешней задачи. | Закрыть внешнюю задачу при невозможной выдаче и проверить, что заявка осталась незавершённой. |
| СТ-ТР-13 | Система должна сохранять состояние окна работ при закрытии связанной внешней задачи. | Закрыть внешнюю задачу незавершённого окна и проверить состояние окна и ресурсов. |
| СТ-ТР-14 | Система должна ограничивать просмотр сведений о связанной задаче областью доступа пользователя к исходной сущности. | Запросить связь чужой заявки от имени сотрудника без доступа и проверить отказ. |
| СТ-ТР-15 | Система должна показывать уполномоченному специалисту время и причину ошибки обмена с внешней системой ведения задач. | Вызвать ошибку связи и ошибку входящего сообщения; проверить время и причину обеих ошибок. |
| СТ-ТР-16 | Система должна предоставлять руководителю ИТ-отдела возможность задавать соответствие состояний внешней задачи состояниям заявки. | Изменить правило соответствия и проверить его действие на подтверждённом изменении задачи. |
| СТ-ТР-17 | Система должна проверять полномочия участника внешнего изменения до выполнения действия над ресурсом. | Закрыть задачу от имени участника без полномочий и проверить неизменность ресурса. |

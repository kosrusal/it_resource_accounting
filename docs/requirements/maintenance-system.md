# Системные требования. Регламентные работы

Редакция 0.4. Проект.

## 1. Термины

| Термин | Значение |
|---|---|
| Ресурс | Учитываемое оборудование, программа или другой объект ИТ-инфраструктуры, который требуется обслуживать. |
| Сервис | Возможность, которой пользуются сотрудники организации. Её предоставление может зависеть от нескольких ресурсов. |
| Специалист | Сотрудник ИТ-отдела, выполняющий обслуживание ресурсов. |
| Пользователь сервиса | Сотрудник, использующий сервис. Пользователь сервиса не обязательно является владельцем ресурса, обеспечивающего его работу. |
| Регламент обслуживания | Документ с правилами обслуживания ресурса. |
| Процедура обслуживания | Описание последовательности действий при обслуживании ресурса. |
| Сведения об обслуживании | Регламенты, процедуры, сведения о месте хранения резервных копий, график обновлений и записи о решённых проблемах. |
| График обновлений | Сведения о том, когда запланированы обновления ресурса. |
| Период предполагаемой недоступности | Время, в течение которого сервис, по оценке специалиста, будет недоступен из-за обслуживания. |

## 2. Документы и сведения об обслуживании

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-13 | Система **должна** позволять специалисту сохранять регламент или процедуру обслуживания с указанием ресурса, к которому относится документ. | Специалист сохраняет регламент одного ресурса и процедуру другого. При повторном открытии видны сохранённый текст и ресурс, к которому относится документ. |
| СТ-РР-14 | Система **должна** предоставлять специалисту регламенты и процедуры обслуживания выбранного ресурса для просмотра. | Для двух ресурсов подготовлены разные документы. При выборе ресурса специалист видит его регламенты и процедуры и может прочитать их содержание. |
| СТ-РР-15 | Система **должна** предоставлять специалисту сведения о месте хранения резервных копий выбранного ресурса. | Для двух ресурсов указаны разные места хранения копий. При просмотре каждого ресурса показаны соответствующие ему сведения. |
| СТ-РР-16 | Система **должна** показывать специалисту график обновлений выбранного ресурса. | Для ресурса подготовлен график обновлений. При просмотре ресурса показанные сроки соответствуют этому графику. |

## 3. Сохранение и поиск решений проблем

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-17 | Система **должна** позволять специалисту сохранять запись о решённой проблеме обслуживания, в которой указаны ресурс, описание проблемы, применённое решение и полученный результат. | Специалист вносит перечисленные сведения. При повторном открытии записи видны сохранённые сведения: ресурс, описание проблемы, решение и результат. |
| СТ-РР-18 | Система **должна** позволять специалисту искать сохранённые решения по словам из описания проблемы. | В описании одной из доступных специалисту записей есть слово, которого нет в остальных. При поиске по этому слову запись появляется в результатах. |
| СТ-РР-19 | Система **должна** показывать специалисту содержание выбранной записи о решённой проблеме обслуживания. | Специалист выбирает найденную запись. В записи видны ресурс, описание проблемы, применённое решение и полученный результат. |

По описанию проблемы специалист узнаёт ситуацию, с которой уже сталкивался.
В записи также указаны действия, которыми устранили проблему, и их результат.
При повторном возникновении проблемы специалист обращается к этой записи.

## 4. Разграничение доступа

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-20 | Система **должна** отклонять запрос на просмотр сведений об обслуживании, если роль пользователя не разрешает ему просмотр этих сведений. | Одному пользователю назначена роль с правом чтения материала, другому — без этого права. Первый получает материал. Второй получает отказ и не видит его содержания. |
| СТ-РР-21 | Система **должна** предоставлять пользователю сервиса предназначенные для него инструкции по использованию этого сервиса. | Для сервиса подготовлены пользовательская инструкция и служебная процедура обслуживания. Пользователь получает свою инструкцию; служебная процедура доступна только при соответствующем праве просмотра. |

Для одного ресурса пользователю показываются инструкции по использованию,
а специалисту — сведения об обслуживании. Ограничение СТ-РР-20 действует
и при показе результатов поиска.

## 5. Влияние работ и предупреждение пользователей

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-22 | Система **должна** по имеющимся сведениям о связях ресурсов показывать специалисту перечень сервисов, на которые может повлиять обслуживание выбранного ресурса. | Подготовлены сведения о сервере, зависимом от него сервисе и независимом сервисе. Перед обслуживанием сервера в перечне присутствует только зависимый сервис. |
| СТ-РР-23 | Система **должна** позволять специалисту указать период предполагаемой недоступности выбранного сервиса из-за обслуживания. | Специалист выбирает сервис и указывает предполагаемый период недоступности. Эти сведения доступны для подготовки предупреждения об этом сервисе. |
| СТ-РР-24 | Система **должна** позволять специалисту предупредить пользователей затрагиваемого сервиса о предполагаемом периоде его недоступности из-за обслуживания. | Известны пользователи сервиса и предполагаемый период его недоступности. После отправки предупреждения они получают сообщение с названием сервиса и указанным периодом. Среди получателей есть пользователь, который не является владельцем обслуживаемого ресурса. |

При обслуживании сервера учитываются сервисы, работа которых от него зависит.
По этому перечню специалист определяет, о недоступности каких сервисов предупредить
сотрудников. В предупреждении указывается сервис, которым пользуется сотрудник,
а не только обслуживаемое оборудование. Предполагаемый период недоступности
не означает, что сервис уже отказал.

## 6. Условия, требующие согласования

| Область | Что остаётся определить |
|---|---|
| Сведения об обслуживании | Какие дополнительные технические сведения нужны о ресурсе? Как вносятся сведения о резервных копиях и как показывается их отсутствие? |
| График обновлений | Кто ведёт график? Как задаются сроки и как показывается отсутствие графика? |
| Материалы и права | Каким ролям разрешены чтение и изменение материалов? Как обновляются устаревшие процедуры и записи о решённых проблемах? |
| Оценка влияния | Какие связи учитываются при определении затрагиваемых сервисов? Что делать, если сведений о связях недостаточно? |
| Предупреждения | Откуда берутся сведения о пользователях сервиса? Когда и по каким каналам отправляются предупреждения? Что делать при изменении периода недоступности или отсутствии получателей? |

Эти условия пока не определены. Проверки, для которых они нужны, выполняются
после их согласования.

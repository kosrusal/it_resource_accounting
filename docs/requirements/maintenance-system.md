# Системные требования. Регламентные работы

Редакция 0.3. Проект.

## 1. Термины

| Термин | Значение |
|---|---|
| Ресурс | Учитываемое оборудование, программа или другой объект ИТ-инфраструктуры, который требуется обслуживать. |
| Сервис | Возможность, предоставляемая сотрудникам организации; её работа может зависеть от нескольких ресурсов. |
| Специалист | Сотрудник ИТ-отдела, выполняющий обслуживание ресурсов. |
| Пользователь сервиса | Сотрудник, использующий сервис. Пользователь сервиса не обязательно является владельцем ресурса, обеспечивающего его работу. |
| Регламент обслуживания | Документ с правилами обслуживания ресурса. |
| Процедура обслуживания | Описание последовательности действий при обслуживании ресурса. |
| Сведения об обслуживании | Регламенты, процедуры, сведения о месте хранения резервных копий, график обновлений и записи о решённых проблемах. |
| График обновлений | Сведения о предусмотренных сроках обновления ресурса. |
| Период предполагаемой недоступности | Время, в течение которого сервис, по оценке специалиста, будет недоступен из-за обслуживания. |

## 2. Документы и сведения об обслуживании

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-13 | Система **должна** позволять специалисту сохранять регламент или процедуру обслуживания с указанием ресурса, к которому относится документ. | Специалист сохраняет регламент одного ресурса и процедуру другого. При повторном открытии сохранены содержание каждого документа и его связь с соответствующим ресурсом. |
| СТ-РР-14 | Система **должна** предоставлять специалисту регламенты и процедуры обслуживания выбранного ресурса для просмотра. | Для двух ресурсов подготовлены разные документы. При выборе одного ресурса специалист получает относящиеся к нему регламенты и процедуры с их содержанием. |
| СТ-РР-15 | Система **должна** предоставлять специалисту сведения о месте хранения резервных копий выбранного ресурса. | Для двух ресурсов указаны разные места хранения копий. При просмотре каждого ресурса показаны соответствующие ему сведения. |
| СТ-РР-16 | Система **должна** показывать специалисту график обновлений выбранного ресурса. | Для ресурса подготовлен график обновлений. При просмотре ресурса показанные сроки соответствуют этому графику. |

## 3. Сохранение и поиск решений проблем

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-17 | Система **должна** позволять специалисту сохранять запись о решённой проблеме обслуживания с указанием ресурса, описанием проблемы, применённым решением и полученным результатом. | Специалист вносит перечисленные сведения. При повторном открытии записи сохранены описание проблемы, решение, результат и указание ресурса. |
| СТ-РР-18 | Система **должна** предоставлять специалисту поиск сохранённых решений по словам из описания проблемы. | В доступной специалисту записи есть слово, отличающее её от других записей. Поиск по этому слову включает запись в результаты. |
| СТ-РР-19 | Система **должна** предоставлять специалисту содержание выбранной записи о решённой проблеме обслуживания. | Специалист выбирает найденную запись. Для прочтения доступны указание ресурса, описание проблемы, применённое решение и полученный результат. |

Описание проблемы позволяет узнать ранее возникшую ситуацию. Применённое решение
описывает действия, которыми её устранили, а результат — что получилось после этих
действий. Специалист использует сохранённую запись при повторном возникновении
проблемы.

## 4. Разграничение доступа

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-20 | Система **должна** отклонять запрос на просмотр сведений об обслуживании, если роль пользователя не разрешает ему просмотр этих сведений. | Двум пользователям назначены роли с правом чтения выбранного материала и без него. Первый пользователь получает материал, второй — отказ без раскрытия его содержания. |
| СТ-РР-21 | Система **должна** предоставлять пользователю сервиса предназначенные для него инструкции по использованию этого сервиса. | Для сервиса подготовлены пользовательская инструкция и служебная процедура обслуживания. Пользователь получает свою инструкцию; служебная процедура доступна только при соответствующем праве просмотра. |

Различие представлений относится к одному и тому же ресурсу: пользователю нужны
инструкции по использованию, специалисту — сведения об обслуживании. Ограничение
СТ-РР-20 применяется также к содержимому, показываемому в результатах поиска.

## 5. Влияние работ и предупреждение пользователей

| Номер | Системное требование | Условие проверки и ожидаемый результат |
|---|---|---|
| СТ-РР-22 | Система **должна** предоставлять специалисту перечень сервисов, на которые может повлиять обслуживание выбранного ресурса, по имеющимся сведениям о связях ресурсов. | Подготовлены сведения о сервере, зависимом от него сервисе и независимом сервисе. Перед обслуживанием сервера в перечне присутствует только зависимый сервис. |
| СТ-РР-23 | Система **должна** позволять специалисту указать период предполагаемой недоступности выбранного сервиса из-за обслуживания. | Специалист выбирает сервис и указывает предполагаемый период недоступности. Эти сведения доступны для подготовки предупреждения об этом сервисе. |
| СТ-РР-24 | Система **должна** позволять специалисту предупредить пользователей затрагиваемого сервиса о предполагаемом периоде его недоступности из-за обслуживания. | Определены пользователи сервиса и предполагаемый период недоступности. После отправки предупреждения пользователи получают сообщение с названием сервиса и этим периодом. Среди получателей есть пользователь, который не является владельцем обслуживаемого ресурса. |

При обслуживании сервера учитываются сервисы, работающие с использованием этого
сервера. Результат оценки влияния помогает специалисту определить, о недоступности
каких сервисов предупредить сотрудников. Предупреждение относится к сервису,
которым пользуется сотрудник, а не только к обслуживаемому оборудованию.
Указанный период — оценка предстоящей недоступности, а не подтверждение фактического
отказа.

## 6. Условия, требующие согласования

| Область | Что остаётся определить |
|---|---|
| Сведения об обслуживании | Состав дополнительных технических сведений о ресурсе; порядок внесения сведений о резервных копиях и отображения их отсутствия. |
| График обновлений | Ответственный за его ведение; способ задания сроков и порядок отображения отсутствующего графика. |
| Материалы и права | Права ролей на чтение и изменение материалов; порядок обновления устаревших процедур и записей о решённых проблемах. |
| Оценка влияния | Состав связей, учитываемых при определении затрагиваемых сервисов; действия при недостаточных сведениях о связях. |
| Предупреждения | Источник сведений о пользователях сервиса, срок и каналы отправки, действия при изменении периода недоступности или отсутствии получателей. |

Эти условия пока не определены. Проверки, для которых они нужны, выполняются
после их согласования.

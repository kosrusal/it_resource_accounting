## 1. Проблема заказчика

Заказчик не знает, сколько свободной ёмкости осталось у сервисов. Для почты нужно видеть, сколько почтовых ящиков включает текущий тариф и сколько сотрудников можно добавить до смены тарифа. Для серверного оборудования нужно видеть свободные ресурсы, чтобы решить, хватит ли их на новый сервис и нужно ли планировать модернизацию.

## 2. Бизнес-требования

| Номер | Требование | Источник |
|---|---|---|
| БТ-МОЩ-01 | Система должна позволять администратору указать для сервиса с тарифом число мест, включённых в текущий тариф | З-07 |
| БТ-МОЩ-02 | Система должна позволять администратору увидеть число занятых и свободных мест в тарифе сервиса | З-07 |
| БТ-МОЩ-03 | Система должна позволять администратору увидеть, сколько сотрудников можно добавить в сервис до смены тарифа | З-07 |
| БТ-МОЩ-04 | Система должна позволять администратору указать ёмкость сервера и долю, занятую сервисами | З-07 |
| БТ-МОЩ-05 | Система должна позволять администратору увидеть свободные ресурсы серверного оборудования | З-07 |
| БТ-МОЩ-06 | Система должна позволять администратору указать требуемые ресурсы нового сервиса и получить ответ, хватает ли свободных ресурсов | З-07 |
| БТ-МОЩ-07 | Система должна позволять администратору получить перечень сервисов и серверов, у которых свободная ёмкость ниже заданного порога | З-07 |

## 3. Границы

Входит: свободная ёмкость тарифов сервисов и серверного оборудования; проверка, хватает ли ресурсов для нового сервиса.

Не входит: автоматический сбор показателей из изолированных сетей (решение заказчика: агенты в таких сетях не нужны); учёт комплектующих (решение заказчика).

Смежное: запас компьютеров по типам рабочих мест относится к разделу «Учёт ресурсов и сервисов» (ПЗ-УЧ, З-06). Связь сервисов с оборудованием ведётся в ПЗ-УЧ (З-08).

## 4. Готовые решения

| Продукт | Что умеет | Чего не хватает |
|---|---|---|
| Zabbix ([zabbix.com/documentation/current/en/manual/introduction/features](https://www.zabbix.com/documentation/current/en/manual/introduction/features)) | Собирает проверки доступности и производительности агентами, по SNMP, IPMI, JMX, VMware; хранит историю в базе данных; задаёт пороги срабатывания (триггеры) | На странице не описаны тарифы внешних сервисов и проверка «хватит ли ресурсов под новый сервис» |
| Prometheus ([prometheus.io/docs/introduction/overview](https://prometheus.io/docs/introduction/overview/)) | Хранит временные ряды показателей; язык запросов PromQL; правила на сохранённых данных для вычисления рядов и оповещений | На странице не описаны тарифы внешних сервисов и расчёт ёмкости под новый сервис; для точного учёта не рекомендуется |

Вывод: оба продукта наблюдают за состоянием серверов; ёмкость тарифа и расчёт для нового сервиса по документации не заявлены.

## 5. Вопросы к заказчику

1. Какие ресурсы сервера учитывать при проверке нового сервиса: процессор, оперативную память, диск, видеокарты?
2. Откуда брать показатели занятости серверов: вводить вручную или загружать из уже работающей у заказчика системы наблюдения?
3. Для каких сервисов, кроме почты, действуют тарифы с ограничением мест?
4. При каком остатке свободной ёмкости заказчик начинает планировать смену тарифа или модернизацию?

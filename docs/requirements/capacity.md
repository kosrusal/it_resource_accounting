## 1. Проблема заказчика

Заказчик не знает, сколько свободной ёмкости осталось у сервисов. Для почты нужно видеть, сколько почтовых ящиков включает текущий тариф и сколько новых сотрудников можно добавить до смены тарифа. Для серверного оборудования нужно видеть свободные ресурсы, чтобы решить, хватит ли их на новый сервис и планировать ли модернизацию (24.10 32:14).

## 2. Бизнес-требования

| Номер | Требование | Источник |
|---|---|---|
| БТ-МОЩ-01 | Система должна позволять руководителю ИТ-отдела увидеть число почтовых ящиков, включённых в текущий тариф | З-07 |
| БТ-МОЩ-02 | Система должна позволять руководителю ИТ-отдела увидеть, сколько новых сотрудников можно добавить в почту до смены тарифа | З-07 |
| БТ-МОЩ-03 | Система должна позволять руководителю ИТ-отдела увидеть свободный объём каждого учитываемого ресурса серверного оборудования | З-07 |
| БТ-МОЩ-04 | Система должна позволять руководителю ИТ-отдела указать объём каждого ресурса, нужного новому сервису | З-07; производное: нужно для БТ-МОЩ-05 |
| БТ-МОЩ-05 | Система должна позволять руководителю ИТ-отдела получить ответ «хватает» или «не хватает» для нового сервиса | З-07 |

## 3. Границы

Входит: свободная ёмкость тарифа почты и серверного оборудования; проверка, хватает ли серверных ресурсов новому сервису.

Не входит: автоматический сбор показателей из изолированных сетей (24.10 17:37); учёт комплектующих (24.10 26:43–28:01).

Смежное: запас компьютеров по типам рабочих мест (З-06) и связь сервисов с оборудованием (З-08) относятся к разделу «Учёт ресурсов и сервисов» (ПЗ-УЧ). Роли определены в общей части постановки (ПЗ, раздел 5).

## 4. Готовые решения

| Продукт | Что умеет | Чего не хватает |
|---|---|---|
| Zabbix ([документация](https://www.zabbix.com/documentation/current/en/manual/introduction/features)) | Собирает проверки доступности и производительности агентами, по SNMP, IPMI, JMX, VMware; хранит данные в базе; задаёт пороги срабатывания | В документации не описаны тарифы внешних сервисов и проверка, хватит ли ресурсов новому сервису |
| Prometheus ([документация](https://prometheus.io/docs/introduction/overview/)) | Хранит временные ряды показателей; язык запросов PromQL; правила на сохранённых данных для вычисления рядов и оповещений | В документации не описаны тарифы внешних сервисов и проверка для нового сервиса |

## 5. Вопросы к заказчику

1. Какие ресурсы серверного оборудования учитывать и в каких единицах?
2. Откуда брать занятость серверов: вводить вручную или загружать из системы наблюдения заказчика?
3. У каких сервисов, кроме почты, есть тариф с ограничением мест? Один почтовый ящик приходится на одного сотрудника?
4. Нужно ли предупреждение о малом остатке ёмкости и при каком остатке?

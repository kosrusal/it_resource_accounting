## 1. Проблема заказчика

Чтобы перезагрузить сервер, специалист вручную выясняет, какие сервисы от него зависят, и сам предупреждает пользователей о недоступности. Если он пропустит сервис или кого-то не предупредит, пользователи узнают о простое, когда сервис уже не работает. Заказчик хочет, чтобы затрагиваемых пользователей определяла система, а предупреждение о периоде недоступности уходило заранее.

## 2. Бизнес-требования

| Номер | Требование | Источник |
|---|---|---|
| БТ-УВД-01 | Система должна позволять специалисту узнать пользователей сервисов, которые затронет запланированная работа | З-15 |
| БТ-УВД-02 | Система должна позволять специалисту заранее предупредить затронутых пользователей о периоде недоступности сервиса | З-15 |
| БТ-УВД-03 | Система должна позволять специалисту сообщить затронутым пользователям о переносе работы | З-15 |
| БТ-УВД-04 | Система должна позволять специалисту сообщить затронутым пользователям об отмене работы | З-15 |
| БТ-УВД-05 | Система должна позволять специалисту сообщить затронутым пользователям о завершении работы | З-15 |
| БТ-УВД-06 | Система должна позволять пользователю видеть предстоящие работы, затрагивающие его сервисы | З-15 |
| БТ-УВД-07 | Система должна позволять специалисту видеть, каких пользователей и о какой работе предупредили | З-15 |

## 3. Границы

Входит: определение пользователей затрагиваемых сервисов, предупреждение внутри системы или по почте, сообщения о переносе, отмене и завершении.

Не входит: оповещение через мессенджеры (исключено заказчиком), служба приёма обращений.

Смежное:
- Какие сервисы затрагивает оборудование, определяют связи «сервис — оборудование» из ПЗ-УЧ (З-08).
- Работы, о которых надо предупредить, берутся из трекера работ ПЗ-РР (З-14).
- Круг пользователей сервиса определяется по правам из ПЗ-ПРВ (З-11); принадлежность пользователей к сервису в семинарах не уточнялась (вопрос 1).

## 4. Готовые решения

| Продукт | Что умеет | Чего не хватает |
|---|---|---|
| Atlassian Statuspage | Плановая работа привязана к затрагиваемым компонентам; подписчикам можно отправить уведомление при создании, начале и завершении; за 60 минут до начала подписчикам почты и SMS приходит напоминание ([документация](https://support.atlassian.com/statuspage/docs/schedule-maintenance/)) | Круг получателей задают подписчики страницы состояния; автоматического вывода получателей из связей «сервис — оборудование» в документации не описано |
| Zabbix, режим обслуживания | Обслуживание задаётся для узлов, групп узлов, триггеров и меток; на время обслуживания подавляются проблемы ([документация](https://www.zabbix.com/documentation/current/en/manual/maintenance)) | Назначение режима — подавление проблем мониторинга; предупреждение пользователей о предстоящей работе на этой странице не описано |

## 5. Вопросы к заказчику

1. Как определить пользователей сервиса: по правам доступа (ПЗ-ПРВ) или по отдельному списку получателей?
2. За какое время до работы нужно предупреждать пользователей и нужно ли повторное напоминание?
3. Должен ли пользователь подтверждать получение предупреждения?
4. Как предупреждать об аварийной работе, которую нельзя назначить заранее?
